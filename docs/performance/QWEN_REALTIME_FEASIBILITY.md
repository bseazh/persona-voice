# Qwen 原生实时语音：接口测试与替换门槛

日期：2026-11-05。关联 Issue #4。延续上轮会话 `946cd6cf-f2cb-4c2e-a50e-cdd53671c4c2` 的优化调查；本报告没有新增真实电话会话。

## 结论

现有服务端密钥可以调用用户提供的北京地域 `qwen-audio-3.1-realtime-flash` 服务。真实接口的语音输入、中文输入转录、语音回答、回答转录均已成功。

**尚未达到正式替换条件。** LiveKit 兼容实验出现自然结束不调用工具、取消后事件处理异常。实验模块未接入 `agent.py`，生产服务未重启，既有 ASR → DeepSeek → TTS 链路保持运行。没有拨打电话，也没有宣称手机端时延或挂断已通过。

这不是单独替换 ASR：主对话将由 Qwen 原生实时模型生成音频和文字，DeepSeek 与独立 TTS 不再处于普通回复的串联路径。报告生成可以继续使用原有 LLM；当前结束语控制器仍需要独立 TTS 播放指定文本，不能假定原生模型支持 `say()`。

## 两次接口级计时

环境：腾讯云现有服务器，服务端 `.env` 中既有密钥；输入为现有 TTS 合成的通用中文测试样本，不含用户真实通话。PCM 单声道输入 16 kHz、输出 24 kHz；按每 20 ms 发送 640 字节，server VAD 阈值 0.5、静音 500 ms。

|项目|第 1 次|第 2 次|
|---|---:|---:|
|样本 PCM 时长|3.100 秒|3.100 秒|
|样本发送完成 → 首块回复音频|0.769 秒|0.872 秒|
|回复音频时长|2.640 秒|2.720 秒|
|输入转录|你好，请告诉我一天有多少个小时？|你好，请告诉我一天有多少个小时？|
|回答转录|一天有24个小时。|一天有24个小时。|
|显式文字结束请求 + required 工具调用|成功|成功|

两次该项均值约 0.821 秒。计时终点是服务器收到音频，不是 LiveKit 房间输出，更不是手机听筒；起点是样本发送完，不是独立标注的人声结束点，样本可能含尾部静音。只有一个通用样本、两次请求，不能据此计算识别准确率、P95 或稳定性，也不能与旧电话测试的 3.601 / 2.820 秒均值直接计算优化百分比。

原生模型未暴露可独立归因的 ASR、LLM、TTS 三段时延，不能伪造各段占比。后续记录：输入语音边界、供应商 speech_stopped、response.created、首音频、房间首播放和客户端实际听到；缺失项标为未测。

## 兼容性验证与失败记录

|测试|结果|解释|
|WebSocket 鉴权、session.update|通过|现有密钥对该端点可用，不代表对其他模型、地域都授权|
|LiveKit RealtimeSession 开场和音频问答|通过|中文输入转录、输出文字与音频均收到|
|后台 generate_reply 结束指令 + required|失败|仍回答前一个问题，没有结束工具；不能依赖单轮 instructions 完成业务控制|
|追加明确用户文字结束请求 + required|通过|收到 finish_consultation 函数事件；此项未执行真实挂断|
|自然音频“今天就聊到这里吧，再见，请挂断电话”|失败|被切成多个片段，出现道别但没有结束工具；期间响应取消|
|自然结束时 SDK 事件处理|失败|LiveKit OpenAI 实时引擎 output_item_done 处理出现 KeyError，需核对取消后的响应/条目归属|
|接现有 ConsultationAssistant / VoiceController|连续两轮失败|均正确回答日常问题并口头道别；均在 25 秒内没有请求房间删除，ending_timeout；第二轮同时捕获 sdk_log:livekit.agents:KeyError|

接口允许 `tool_choice=auto/none/required`，但拒绝按名称指定工具的对象形式。Qwen 没有回传 OpenAI 引擎用于关联显式生成请求的 response metadata。实验桥只实现有限关联，尚未证明显式请求与自动 VAD 响应并发时可靠，因此不能仅凭单轮工具调用成功上线。

对话控制器探针使用按音频时长消费的测试 sink，不向扬声器播放；房间删除由本地记录器捕获，没有删除真实房间。这样能检查现有控制器是否走到关闭阶段，不能证明 WebRTC、SIP、SIM 挂断成功。

## 下一步：先解决门槛，再替换

1. 实现并验收按 response_id / item_id 关联的取消与迟到事件处理，不能简单吞掉 KeyError；显式生成与自动 VAD 并发时不能错配。
2. 独立处理明确结束意图及业务方结束请求。状态机负责唯一结束语、关闭请求和下游确认，不能只靠模型自愿调用工具；模糊结束表达需确认。
3. 覆盖两轮连续问答、说话中停顿后继续、插话、自然结束、后台结束、异常断线和转录保存。各项至少重复两次，失败退出码不算通过。
4. 验收后增加可回退的生产模式开关，保留旧链路；以两通真实电话测试验证听筒时延、单次结束语和实际挂断。每通仍单独提交 Issue 结果，不自动追加第三通。

当前决策：**保留原生 realtime 实验方向，但不把已知有挂断/取消问题的兼容桥设为线上默认。**
