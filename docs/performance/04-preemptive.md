# 04 提前生成：能否把模型等待与收尾重叠？

## 当前结论

GitHub Issue：[本阶段测试与优化历史 #4](https://github.com/bseazh/persona-voice/issues/4)。

实施 preflight-v1：稳定中间识别触发 LiveKit 官方 PREFLIGHT_TRANSCRIPT，仅提前生成 LLM 候选，正式转录确认后才允许播放与执行工具。真实电话效果待两次测试。

## 优化前

参考上一阶段：[第1通](tts-duplex-v1-1.md) 5轮非中断回复，均值2.910秒；[第2通](tts-duplex-v1-2.md) 3轮，均值2.537秒。自由话题、小样本，不能作为严格控制实验或声称因果收益。

## 计划变更与原因

中间识别至少6字符、稳定300ms后提供候选；每ASR句最多2个不同候选，SDK每用户轮最多2次尝试、说话超过10秒停止提前生成。保持 baseline 停顿参数与 duplex-v1 TTS；关闭提前TTS。

LiveKit 1.8.10 在采用候选前校验最终文字、上下文、工具配置；文字变化时取消旧候选。工具执行受正式轮次授权约束。不会将 interim 伪造为 FINAL。

新增稳定提示取消、去重、预算、关闭与异常隔离5项测试；现有TTS并发2项、结束播放2项回归测试通过。SDK授权门源码已检查；真实通话中抢话、打断与结束行为仍须验收。

观测 asr_preflight / asr_final 时间、生成取消状态与原有轮次计时。生成记录不代表实际播放；SDK transcription_delay 受预识别时钟影响，不作为真实FINAL等待的独立依据。并行阶段不强制计算100%占比；不宣称已经测得手机端听音时延。

回滚：服务端设置 VOICE_PREFLIGHT=off，在无通话时重启 Agent。额外候选可能增加 LLM token 费用，先以两通测试评估，不扩大自动呼叫数量。
