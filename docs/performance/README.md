## 当前实际结果

新线路测试已产生真实数据：一通 7 个完整回复，均值 2.879 秒；另一通仅 1 个非中断完整回复，3.550 秒，另记录两次中断。两通均结束语播放后归档。详情、逐轮占比和各次 Issue 评论见 [基线结果](01-baseline.md)。此前新线路第 1 次尝试因安卓允许名单遗漏被 403 拒绝，现已修复。基线未达到两通各至少 5 轮，四项优化仍未实施。

2026-11-05 旧线路尝试两次，均 `phone_not_connected`，各有 0 个有效轮次。拨号等待约 34.37 秒，仅表示未接通等待，不能当作 AI 响应延迟。没有测得 ASR、LLM、TTS 分段耗时及占比。

用户随后调整主被叫并更换 SIM，软件仍使用 SIM 2（逻辑槽位 1）；手机系统显示中国移动卡，完整号码被系统隐藏。新线路必须重新完成两通基线，实际主叫以接听手机来电显示为准。完整号码与私人转录不写入本档案。

## 每轮必须回答的问题

1. 优化前卡在哪里？给出两通有效测试的会话 ID、逐轮时间和异常。
2. 本轮具体改了什么？为什么？保留参数与代码版本。
3. 优化后两次分别怎样？给出分段时间、占比、总等待、打断及听感。
4. 比前一阶段改善还是退步？不能量化时标记“待测”，说明原因；决定保留或回滚。

基线两通；每项优化增加两通，前值引用紧邻上一阶段的两通，共至少 10 通有效电话。失败尝试单列且不覆盖。每通至少 5 轮，固定模板与网络环境，包含停顿、插话、结束语。

## 如何维护

每个阶段一个 Issue。每次测试使用模板追加 Markdown 评论，附唯一会话 ID、代码版本、配置、逐轮耗时、异常及人工反馈。失败拨号也要提交，标明无有效样本。不得覆盖前一次结果；修正数据应追加更正说明。两通完成后补优化前后差值、比例及保留/回滚决策，检查后关闭阶段 Issue。

`scripts/benchmark-phone.cjs` 保存私人原始事件，`scripts/report-phone-latency.py` 生成本地逐轮 Markdown 报告；提交前只提取白名单计时字段到本目录，禁止提交 API Key、管理员密码或完整健康转录。GitHub 提交失败时必须标记“待同步”，保留会话 ID 并核对有无重复评论，不得声称已发布。

当前没有实施四项优化，也没有宣称优化收益。已部署的只是 SDK 计时日志；两个语音结束流程测试通过。
