# 检索等待与电话时限收尾优化

2026-11-06。用户要求先修改，后续再由本人接听验收；本轮没有拨打真实电话。

## 诊断依据

上一通接通到 ended 约179.84秒，最后回答被截断，未收到再见指令。读取线上 Asterisk 拨号计划确认：电话出口 Dial 带 `L(180000)`；livekit-ai 同时有 `TIMEOUT(absolute)=180` 和 `L(180000)`。Agent 原来只在900秒后申请结束，明显晚于电话硬截止。

现存逐通日志没有保留可用的“本次由定时器触发”记录，因此不能把参与者断开事件单独当成硬超时证明；但180秒配置与实际断开时间高度吻合。本次保留电话硬上限，补提前收尾机制。

检查已安装 LiveKit Agent SDK 的实时工具路径：工具完成后要等当前音频播放/排队结束、更新模型会话并收到同步确认，然后申请下一次生成。不能直接绕过这些步骤，否则可能破坏取消、上下文顺序与插话隔离。

## 变更

- `services/agent/procurement_knowledge.py`：按查询中的明确型号优先选择对应正文，优先已审阅的中文参数摘要；多型号比较保留各型号，找不齐不硬过滤。原文片段上限从2200字符降为1600；短标题不作为优先参数证据。工具只回传状态、正文和来源URI，完整来源哈希等仍留审计。复用会话内HTTP连接，结束时关闭，不引入跨会话缓存或预设答案。
- `services/agent/qwen_realtime.py`：新增同一进程时钟的工具参数完成、工具输出发送、生成请求、首个有效音频事件。新字段不记录音频或凭据。Qwen支持独立的时限告别：“通话时间快到了，我们先聊到这里，再见。”
- `web/app/api/consult-agent/route.ts`：open/heartbeat返回服务器计算的电话剩余时间，优先取本通connected事件；尚无该事件时从创建时间保守计时（可能更早收尾）。网页会话不返回电话时限。
- `services/agent/realtime_voice.py`：使用本地单调时钟记录截止点，只能收紧不能被后续心跳延长；心跳单次最多等3秒，已有截止计时不依赖持续成功的心跳。正常约接通140秒开始收尾，留40秒余量。关闭新音频输入，当前回复最多等5秒，之后取消并播放告别；收尾总预算25秒，电话释放等待最多8秒。保留180秒硬兜底。过长的当前回复仍可能在5秒后中断，不能承诺异常网络下必然完整告别。
- `services/agent/agent.py`：把后端电话时间预算传入实时控制器，并注册知识HTTP会话关闭回调。电话提前收尾当前作用于实时路线，传统ASR→LLM→TTS控制器未在本轮改动；网页900秒规则不变。
- 回归：`tests/test_procurement_knowledge.py`、`tests/test_realtime_ending.py`；探针关闭HTTP资源：`scripts/probe-qwen-openviking.py`、`scripts/validate-procurement-corpus.py`。
