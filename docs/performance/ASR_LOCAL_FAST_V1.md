# 识别收尾：local-fast-v1 实验

用户要求先优化，再测试两通。2026-11-05 实施本地收尾策略实验，TTS 继续使用当前千问，不开启提前生成，不改变自由对话提示词，不伪造 ASR 最终结果。

|参数|原配置|实验配置|
|---|---|---|
|Silero 静音确认|0.500 秒|0.350 秒|
|轮次最小等待|0.450 秒|0.300 秒|
|轮次最大等待|1.500 秒|1.500 秒|
|转录超时上限|4.000 秒|4.000 秒|
|提前生成|关闭|关闭|

选择原因：SDK 源码显示轮次等待根据最后说话时间扣除已经过去的时间，并且最终转录与 VAD 存在重叠。ASR 早完成的轮次有机会减少本地等待；最终转录迟到的轮次可能无收益。不能把两项减少相加成固定减少300ms，也不能保证每轮加速。

没有确认千问当前模型支持可调句末静音参数，因此不向供应商传入猜测参数。本次是本地endpointing优化实验，不宣称修复了供应商最终结果延迟。

通过 VOICE_TURN_PROFILE=baseline 可恢复旧值；默认 local-fast-v1。会话 benchmark_config 会记录实际profile、参数、TTS供应商/模型/音色，便于复盘。

测试两通：每通尽量5轮以上，分别包含短句、长句、约半秒句中停顿、插话、主动结束。逐轮采集最终转录、收尾、LLM首字、切句、当前千问TTS首音频、总等待。误切句、抢话、漏字和打断体验与速度同等重要。

对照限制：此前7轮完整样本来自睡眠调研；自由对话没有两通足量的优化前样本。该历史对照只作方向参考，不把不同问题和供应商抖动归因于本次代码。两通优化后结果必须分别追加 Issue #2，再决定保留或回退。
