# 01 基线：当前链路实际耗时是多少？

## 当前结论

GitHub Issue：[本阶段测试与优化历史 #1](https://github.com/bseazh/persona-voice/issues/1)。

旧线路两次未接通保留历史。新线路本轮进行了三次尝试：一次网关 403 拒绝、一次完成 7 个非中断回复计时、一次短通话只有 1 个非中断回复。因此已获得真实分段数据，但仍缺第二通至少 5 轮的完整基线，不进入优化阶段。

## 优化前

代码来源 ee37753，测量版本 1，语音策略未改变。第 1 次失败后补齐安卓允许名单，这是拨号前置修复，不计为 ASR/TTS 优化。

## 计划变更与原因

只增加统一计时，不改变语音策略。换卡后重测两通。

## 本轮解答与决策

第一通 7 个完整回复的阶段均值如下；占比为阶段累计时间 / 总累计等待时间，不是各轮百分比的简单平均。

|阶段|均值（秒）|占比|
|---|---|---|
|轮次收尾（含与转录重叠的等待）|1.409|48.9%|
|模型首字|0.718|24.9%|
|首字后切句|0.222|7.7%|
|TTS 首音频|0.510|17.7%|
|其他调度残差|0.021|0.7%|
|服务端总等待|2.879|100%|

初步支持先优化收尾，但只有一通足量样本，不宣称收益或稳定性。两通已接通电话均 farewell_played、未记录 voice.error。第二通记录到中断，手机实际打断速度及听感尚待人工确认。下一步补足第二份基线；本轮不改语音策略，不继续自动拨号。
