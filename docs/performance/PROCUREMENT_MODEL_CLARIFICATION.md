# 采购型号澄清循环优化（2026-11-06）

## 真实电话问题

本轮采购全双工电话中，用户连续补充“Phoenix”“P H O E N I X”“1600”“筛筒长和直径”，助手仍三次重复询问具体设备，未触发 Phoenix 检索。同通电话 TSS 390 与 TDS 825 均成功调用 OpenViking，检索分别为 431 ms、631 ms，参数回答正确。因此已确认的失败点是进入检索前的型号理解/澄清策略，不能归因为库里没有资料。具体语音切段对失败的贡献尚未单独测量。

## 修改

- `services/agent/procurement_knowledge.py`：预加载六个型号名称与类别，不预加载参数答案；引导结合相邻话语、数字、类别和拼写，明确换型号时跟随新型号。
- 同一型号最多澄清一次；有足够线索先查候选，未完全确认用条件句回答。单独“1600”不直接认定型号。
- 检索端将“phone next / P H O E N I X + 1600”或“1600 + 筛筒”扩展为 Phoenix 候选，保留原始查询和检索查询供审计，不改用户转录，不对孤立数字或其他设备尺寸硬映射。
- 参数回答控制在一两句，避免每轮重复长免责声明和索要配置单。
- `scripts/probe-qwen-openviking.py`：支持多轮用户文字输入；预期数值只核对最后一条回答，防止早先回答掩盖当前失败。
- `tests/test_procurement_knowledge.py`：增加语音别名、孤立数字、其他型号及数字边界回归。

## 验证

第一轮真实 Qwen + OpenViking 回归已能回答补充拼写后的问题，但发现孤立“1600”仍可能被直接认作 Phoenix；据此收紧条件回答规则，再进行最终回归。

最终真实多轮结果：

> 用户：我想问一下1600的尺寸。
>
> AI：您说的是滚筒筛吗？
>
> 用户：phone next，就是 P H O E N I X，1600，筛筒长和直径大概是多少？
>
> AI：如果您指的是 Phoenix 1600 滚筒筛，手册上写的是筛筒长度 4.9 米，直径 1.54 米。

实际云端工具调用成功、27 个音频帧、错误事件为零。证据文件 `qwen-openviking-1793934678678295000.json`。使用文字触发并将音频按时输出到丢弃端，不是麦克风识别、真人听感或新电话验收，不声称已经修复供应商 ASR。

检索边界/候选测试 5 项、实时控制回归 8 项通过；六型号云端检索 6/6 通过，本轮单次检索 214–574 ms，不是端到端语音时延。没有修改 VAD、音频缓冲、取消或挂断控制。

## 发布与下一次验收

确认 Asterisk 无活动通话、LiveKit 无房间后，仅同步修改的 Agent 知识模块并重启 Agent；源码提交使用 skip ci，避免文档同步再触发全站重启。新会话加载新规则，已经建立的会话不热更新。

下一通重点验收：分段说 Phoenix 1600、只说数字后补类别、从 1600 换成 3300、问未知型号；检查是否只澄清一次、是否实际检索、是否混型号。最终文字联调通过不等于上述电话行为已经全部通过。
