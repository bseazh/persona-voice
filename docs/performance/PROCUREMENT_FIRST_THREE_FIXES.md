# 采购对话前三项优化

2026-11-06；对应五项基线中的报告准确性、答疑节奏、对比对象确认。本轮不修改音频传输、VAD、电话时限或挂断逻辑，也没有拨打新电话。

## 修改范围

1. `web/lib/procurement.ts`：删除具体处理量示例；把答疑与采购采集明确分开。用户问参数时简短回答后停止，只有为回答当前问题必须的澄清才追问。缺少比较对象时确认最近讨论型号；明确换型号时回答新型号，不套用旧参数。
2. 同文件新增报告证据校验：模型选择本次原文，服务端核对消息/项目字段、角色和逐字引用；跳过被打断的助手消息。真实回归中发现模型偶尔改写引用，因此引用不匹配时直接展示对应来源的原始前180字，并记录 source_excerpt_fallback，不发布模型添加的文字；来源不存在或角色不符仍拒绝。不支持自由编写无来源的事实摘要，改为简明来源摘录，后续建议独立标识。原文匹配只能验证引用来源，不能证明原话属实或识别无误。
3. `web/lib/consultation.ts`：采购报告不再把历史抽取 facts 当成生成依据；只接收本次项目表和消息，保存可核对的 evidence。旧的未经核验字段不沿用到新报告。来源校验失败会走现有报告失败/重试流程，不以伪造值补齐。已有 ready 报告不自动覆盖。
4. `services/agent/procurement_knowledge.py`：同步答疑优先、比较对象规则，消除基础采购提示词仍要求每轮追问的冲突。
5. `scripts/test-procurement.cjs`：增加无来源数值、角色不匹配、被打断消息、空项目字段及建议冒充承诺的拒绝测试；加入 GitHub Actions。
6. `scripts/probe-procurement-report.cjs`：使用已有转录和真实 DeepSeek 验证报告，不写生产会话。`scripts/probe-qwen-openviking.py` 支持实际业务提示词文件，以完整采购指令联调而非简化指令。

## 验证结果

- 报告校验与采购模板测试通过；OpenViking 5 项回归通过；前端 lint、生产 build 通过。
- 使用上一通真实转录进行真实 DeepSeek 回归：原文引用校验通过，不再产生“十五吨”；助手资料与对方原话分开，建议标注“未形成双方承诺”。这不是重新拨号，未改写历史报告。
- 真实 Qwen + OpenViking 三轮：1600 答 4.9 / 1.54 米，2100 答 6.45 / 1.94 米，均未附加物料/筛孔追问；问“3300有什么不同”时只问“您是要和刚才的2100比较吗？”。证据 `qwen-openviking-1793937160736627000.json`。
- 另一次四轮：最后明确比较3300与2100，回答 9.31 / 2.32 米与 6.45 / 1.94 米，差值2.86 / 0.38米正确，无无关追问。该次模糊比较问题只答了3300本身尺寸，没有主动澄清，但没有再擅自选1600作对比。证据 `qwen-openviking-1793937250355416000.json`。

这些是真实模型、真实检索、文字输入与定时丢弃音频输出的联调，不是手机ASR或听感验收。模型澄清行为仍有波动，不能声称每次都会严格按相同句式确认；下一通重点检查分段语音、明确换型号、隐含比较对象、问答后是否强行追问。

## 报告行为变化与限制

报告事实部分采用带来源的原文摘录，优先可追溯性，措辞不会像自由摘要那样流畅。没有改变原始转录；来源保存于 report.evidence。供应商原话不自动成为承诺，助手发言不自动成为供应商确认。对原话本身的真实性仍需人工及书面资料核验。建议不会指派已承诺责任或具体期限；实际承诺如存在，应在来源摘录中保留。

发布后新会话及尚未生成的采购报告使用新规则。已归档的旧报告保留，避免静默篡改历史记录。电话中的真实验收和结束控制仍按五项基线分别追踪。
