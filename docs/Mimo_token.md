## 计费口径

官方价格：https://mimo.mi.com/static/docs/price/pay-as-you-go.md

- MiMo ASR `mimo-v2.5-asr`：国内 ¥0.5 / 输入音频小时，**不是按 token 计费**。优先使用响应 `usage.seconds`，不用通话时长或本地音频时长冒充供应商计费时长。
- MiMo TTS `mimo-v2.5-tts`：当前限时免费，因此本报告 TTS 费用估算为 ¥0；不代表永久免费。
- 接口仍返回 `prompt_tokens`、`completion_tokens`、`total_tokens`，如下保留原始计数。它们不能自行乘以通用 LLM token 单价。
- 以下历史测试表的费用仅为 MiMo 语音接口按公开价格估算，不是账户正式账单。新增的 Pro / Ultraspeed 三组件预算见上文；实际 DeepSeek 对话/报告、SIM 话费、服务器另计。
- 每分钟费用 = 本通语音费用 ÷ 实际接通至通道关闭秒数 × 60。用户说话占比不同，价格也会变化；一分钟通话不等于一分钟 ASR 输入。
- ASR 为本地 VAD 分段后上传 WAV，不是持续双向音频输入；无中间识别，故本路线关闭提前生成。TTS 按句输入、SSE 音频输出。

LLM 首字包含在“LLM 开始 → 首段送 TTS”内，不能重复相加。上述计时不是手机听筒端到端时间。三分钟六个 ASR 请求的提交开始 → 完整结果耗时为 0.499、0.902、1.450、1.189、1.614、1.812 秒，平均 1.244 秒；一分钟测试同口径平均 0.577 秒。ASR 耗时包含上传与服务端往返，不等于纯推理；该计时也不包括前面的 VAD 分段等待。

**结论：路线跑通且可计量，但没有证据表明换 MiMo ASR 后降低了总响应时延。** 三分钟样本反而有更长的 ASR 往返和合成首音频等待。问题长度、音频长度及服务抖动可能影响结果，未做同音频受控 A/B，不能断言是模型或网络单项造成。voice.error 为 0，但不是自然交互体验全部通过。
