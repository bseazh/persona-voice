# 公网咨询工作台

入口：https://phone.hehaizhao.site/consult

## 当前使用流程

1. 使用独立工作台管理员密码登录（有效期 12 小时），不是旧语音访问码。
2. 填写咨询标题，确认文字保存说明，开始睡眠与生活习惯调研。
3. DeepSeek 根据真实输入逐轮生成回复；每轮通常问一个主要问题。支持跳过、拒答和结束。左右气泡展示原话，右侧为带原文依据的结构化摘要。
4. 点击结束按钮或在对话中要求结束，AI 生成结束语，自动进入归档页生成简报。模型请求失败可重试；原转录仍保留。
5. 分别下载报告和完整转录两个 Markdown 文件。时长是创建至结束的文字咨询时长，包含等待和输入，非电话接通时长。

本轮使用真实模型，不是离线演示。页面按轮显示完整回复，活动会话每 2.5 秒刷新；尚未实现逐字流式输出、语音通话的实时字幕或知识库检索。当前为单一业务管理员工作台，不是多租户或面向受访者独立登录的系统。

## 填写千问 ASR / TTS Key

登录 → **语音配置 · 填写 Key** → 填写北京业务空间 ID 和共用 API Key → 保存共用 Key。

- 默认业务空间：`llm-w115702gcv6zwvwy`，需与新 Key 匹配。
- TTS：点击「合成测试语音」，服务器合成固定测试句，返回 WAV 后点击播放器试听。
- ASR：选择 3–10 秒清晰人声文件（最多 5MB），点击「识别上传语音」。服务器转换为 16kHz 单声道 WAV 后请求录音 ASR。
- 模型分别是 `qwen-audio-3.1-asr-flash` 和 `qwen-audio-3.1-tts-flash`，TTS 音色 `longanhuan_v3.1`，输出 24kHz PCM 包装 WAV。
- 不会使用历史 `.env` 中的 Qwen Key 作为后备。此配置只供工作台测试，尚未同步至 LiveKit Agent 或启用电话。录音 ASR 测试通过也不等于实时 ASR、电话双向音频通过。
- Key 经 HTTPS 提交、AES-256-GCM 加密后存 PostgreSQL，不回显。不要再把 Key 发在聊天、Git 或截图中。
- 不需要开放新公网端口；接口通过现有 HTTPS 443、登录 Cookie 和来源校验保护。

## 电话配置边界

「电话线路」读取现有私有控制台状态，可保存主叫号码备注、接听号码和 SIM 偏好。保存不会改手机卡槽、实体主叫号码、Asterisk 白名单或立即拨号。拨号按钮始终禁用，待后续语音和线路验收后再接入。SIP 注册不代表全部音频链路正常。

## 持久化和审计

PostgreSQL 保存会话、原始文字、模板版本、事实来源、报告、事件、凭据密文和登录会话。数据库仅本机监听。原始对话和模型的审计摘要可能包含健康信息，仅授权管理员可读。

结果页管理员折叠区可检查每轮动作、简短依据、来源消息 ID、模型调用耗时、token 用量、成功/失败、报告及导出事件。记录可解释的执行依据，不记录模型隐藏思维。未接入知识库，检索来源目前为空，不能据此声称有外部证据支持。

保存每条用户消息后再调用模型；请求 ID 防止重试重复插入。每会话数据库租约避免同时生成，进程异常后最多等待 90 秒再重试。单次上游请求 60 秒超时。达到 12 轮或 30 分钟后，下一次请求会收尾；不是定时器自动挂断。

资料默认持续保留，当前没有自动过期策略。结果页删除会删除该会话、消息、报告及会话事件，保留一个删除审计标记；已下载文件不随之删除。开始正式业务前应制定保留期限及备份策略。

## 部署与恢复

依赖：Node 22.22+、PostgreSQL、ffmpeg、现有 Agent Python 虚拟环境及 DashScope。

服务器首次准备 PostgreSQL 后，运行 `python3 scripts/setup-consultation.py`。脚本生成独立数据库角色、管理员密码和加密密钥，写入服务器 `.env`，不会覆盖 DeepSeek 或旧语音凭据。再次运行保留已有配置。管理员登录说明写入被 Git 忽略的 `BigApple输出/consultation-access.txt`，权限 600。

环境变量：`DEEPSEEK_API_KEY`、`CONSULTATION_DATABASE_URL`、`CONSULTATION_ADMIN_PASSWORD`、`CONSULTATION_ENCRYPTION_KEY`、`CONSULTATION_PUBLIC_ORIGIN`、`PERSONA_PROJECT_ROOT`；可选私有状态查询 `PHONE_CONSOLE_PASSWORD`。均不得使用 `NEXT_PUBLIC_` 前缀。

现有 GitHub Actions 在 main 推送后构建并部署。数据库位于 PostgreSQL 数据目录，部署同步不会删除它；`.env`、`BigApple输出/` 不参与发布覆盖。应把 PostgreSQL 备份和 `.env` 中加密密钥分别保存到受控位置。丢失加密密钥后需重新填写语音 Key，单独恢复数据库无法解密原 Key。此版本尚未配置自动异地备份。

## 常见排查

| 现象 | 检查与处理 |
| --- | --- |
| 未登录返回 401 | 正常访问控制，进入 /consult 登录；不要用旧语音访问码 |
| 请求 403 | 检查公网域名与 `CONSULTATION_PUBLIC_ORIGIN`、Origin 和 X-Consultation 标头 |
| 页面 503 | 检查 web 服务、PostgreSQL 服务和数据库环境配置；不要把完整环境输出贴入日志 |
| DeepSeek 401/402/429 或超时 | 核对服务端 Key/额度/限流/出口；本次用户消息已保存，同一输入重试不会重复插入 |
| 会话正在处理 409 | 等待当前请求完成；异常退出后租约最长 90 秒，可刷新再试 |
| 报告失败 | 转录仍在，点击重新生成报告；不要为修复报告而删除会话 |
| 千问尚未配置 | 在语音配置保存新 Key，不会回退使用历史泄露 Key |
| 千问 401/403 | 核对 Key 与北京业务空间、模型权限 |
| ASR 无文字 | 先本地试听文件，检查是否有清晰人声；文件有波形不一定有人声 |
| TTS 无音频 | 核对模型权限、额度、Python DashScope 环境及出口，成功后手动点播放器 |
| 线路状态不可用 | 检查本机 5055 服务及私有状态凭据，不需要把 5055 暴露公网 |

文字咨询不是医疗诊断。风险提醒和报告由模型生成，应结合转录核对；无可用语音 Key 时不得把配置页面上线描述成语音链路已验收。
