# 调试复盘：从浏览器语音到 SIM AI 电话

整理日期：2026-11-03。对应稳定基线：`v1.0.0`。

本文记录本次调试的关键证据、决策和验证结果，不是所有历史日志的完整归档。未保留原始诊断证据的地方明确标为“根因未确认”，不根据报错文字补造结论。日常操作见 [故障排查手册](TROUBLESHOOTING.md)。

## 1. 最终跑通的链路

```text
浏览器 ── WebRTC ─────────────────────────────┐
                                            ↕
接听手机 ↔ SIM 拨号手机 ↔ Asterisk ↔ LiveKit SIP ↔ 自建 LiveKit
                                            ↕
                                  千问流式 ASR → DeepSeek → 千问 TTS
```

实际部署与端口以 [自建说明](../ops/SELF_HOSTED.md)、[SIM 桥接说明](../ops/SIM_AI.md) 为准。USB 是调试和配置通道，不是电话音频传输通道。

## 2. 调试阶段与决策

| 阶段 | 现象 / 需求 | 处理与结果 |
| --- | --- | --- |
| 早期模拟语音 | 422、Base64 解码失败、音频源无效 | 用户要求淘汰模拟前端，迁移 LiveKit；不再沿用旧音频 URL 回复方案 |
| 浏览器识别拆分 | 一直聆听、无法确认输入是否有效 | 增加音量检查和录音识别模式，将录音、ASR 与实时通话分开验证 |
| 千问接入 | 识别无文字、400、TTS 凭据问题 | 增加音频指标与错误分类，独立测试 TTS；最终采用千问 ASR/TTS |
| 实时化 | 手动录音能识别，希望自然对话 | 使用持续 WebSocket ASR、VAD、流式 LLM、分句 TTS |
| 媒体服务迁移 | Cloud 区域请求超时、连接失败 | 迁移腾讯云自建 LiveKit，验证浏览器 RTP 和合成语音往返 |
| SIM 音频验证 | 接通电话但无声 | 先用 Asterisk 回声隔离 AI；修复 RTP 网络问题，验证双向音频 |
| AI 电话桥接 | 回声已通，希望接入 AI | 部署本机 LiveKit SIP、受限 trunk、自动 Agent dispatch，再做真实电话测试 |

## 3. 关键问题记录

### 3.1 旧模拟页面：422、atob 与无效音频源

- **现象**：旧 `/api/conversation` 返回 422；浏览器出现 `atob` 编码错误、`no supported source`、语音回复地址无效。
- **证据边界**：存在历史报错记录，但本文没有足够原始请求、响应和旧代码证据，不能确认每一次报错的唯一根因。
- **处理**：按用户要求删除模拟语音前端，改为 LiveKit 音频轨道；不再依赖旧接口和临时回复地址。
- **教训**：旧接口的 422 与当前 `/api/transcribe` 的 422 不是同一个故障。先确认 URL、版本和响应体，再判断原因。

### 3.2 ASR 无有效文字，不等于 Key 失效

- **现象**：录音识别返回空文本或千问无语音文字错误；用户后来更换耳机并确认能够识别。
- **已做改进**：服务端 FFmpeg 标准化为 16 kHz 单声道 WAV；记录录音大小、音频指标、上游请求编号；区分近静音和“有信号但无识别文字”；增加入房音量检查。
- **不能断言**：不能仅凭换耳机后成功，就认定所有历史失败都由耳机造成；也不能把有音量当作有清晰人声。
- **验证**：录音模式识别成功后，再验证实时模式。`ASR_MODE` 控制实时 Agent 的适配器，不控制录音接口。

### 3.3 百炼 TTS：Key 与 workspace 不匹配

- **证据**：候选 Key 调用返回 400，错误明确要求 `X-DashScope-WorkSpace` 与该 Key 绑定的业务空间匹配。
- **已确认原因**：此次候选凭据与 workspace 组合不匹配。不是“所有千问 TTS 均不可用”，也不能归因于浏览器音量。
- **处理**：按用户要求继续使用原来可用的 Key；保留独立 TTS Key/workspace 配置入口。
- **验证**：独立 TTS 脚本生成约 7.33 秒、有效非静音 PCM WAV；之后在实时链路和 SIM AI 通话中验证回复音频。
- **教训**：先单测供应商，再查 LiveKit 轨道和播放设备；不要一次同时修改 Key、模型、音色与网络。

### 3.4 Cloud 超时与连接生命周期

- **现象**：Cloud `settings/regions` 请求超时，出现 `cannot negotiate on closed engine`；还出现过 `Client initiated disconnect`。
- **证据边界**：Cloud 访问超时已观察到，但未证明是所有地区均不可用或某一种运营商故障。`CLIENT_INITIATED` 也可由正常挂断产生，不天然代表异常。
- **处理**：前端显式管理 Room 生命周期、连接超时、取消和麦克风初始化；迁移到腾讯云自建 LiveKit。
- **验证**：HTTPS/WebSocket 入口正常；浏览器媒体连接至腾讯云 UDP 5053，实际收发数据；合成语音测试两轮识别、回复及打断通过。
- **剩余限制**：未部署 TURN/TLS，限制媒体端口的网络仍需额外验证。

### 3.5 SIM 接通无声：信令通，但 RTP 不通

- **关键证据**：故障时手机捕获到非静音信号，发送约 1,797 包但接收为 0；服务器接收为 0，并向私网地址发送提示音，无法通过入站 RTP 学到公网媒体地址。
- **原因与处理**：结合防火墙状态和修复后的结果，确认当次 RTP 网络放行问题；开放 Asterisk 对应 UDP 10000–10019。SIP TCP 5054 和 LiveKit UDP 5053 不能代替这个端口范围。
- **验证**：回声测试中双方有包、非静音，采样期间无丢包；用户确认接听端能听到提示音和自己的回声。
- **教训**：SIP 注册、电话接通、`audioReady=true` 都不等于真实双向声音成功。

### 3.6 换卡后槽位不一致

- **证据**：手机报告唯一有效 SIM 为 `1:中国广电(sub3)`，但旧 `default_sim` 与 `X-VSA-SIMSLOT` 为 `0`。
- **处理**：默认 SIM 与 Asterisk 头同步设为逻辑槽位 `1`（界面上的 SIM 2）；同步接听号码白名单和拨号目标。
- **验证**：网关状态、服务器拨号计划一致，之后真实电话接通。
- **教训**：实际 SIM 号码以用户提供和实体卡为准，不能通过 SIP Caller ID 设置成任意号码；换卡后必须重新检查槽位。

### 3.7 SIP 桥部署与音频测试夹具

- **镜像网络**：直连 Docker Hub 拉取超时；改用腾讯镜像源获得 LiveKit SIP 1.22.0，部署固定镜像 digest，避免后续随 `latest` 漂移。没有关闭 TLS 验证。
- **路由**：SIP 桥只监听本机 127.0.0.1:5060；Asterisk 使用独立 127.0.0.1:5062 传输。trunk 限制本机来源及目标 9000，dispatch 为每次通话建立独立房间并启动指定 Agent。
- **测试夹具问题**：Asterisk 报 `File custom/persona-sip-test does not exist`。`core show settings` 显示该发行版 Data directory 为 `/usr/share/asterisk`，此前音频放到了 `/var/lib/asterisk/sounds`。
- **修复**：将 8 kHz 单声道 WAV 安装到实际声音目录后，夹具语音被正确识别，AI 返回相关回复。
- **观察脚本问题**：初版错误使用 AudioStream 上下文管理方式，任务异常未显式抛出，导致输出零帧，不能据此判定真实链路无声。改为显式创建/关闭流并传播任务异常；最终真实电话观察获得双向非零音频。

### 3.8 模型答复过时，但音频链路正常

- **证据**：真实测试时用户询问最新手机，模型将旧型号当作最新型号回答。
- **原因**：未接入实时搜索；模型已有知识不能作为实时事实。
- **处理**：提示词要求时效性问题明确说明无法实时核实。
- **限制**：该调整不能保证消除幻觉；需要准确实时信息时应新增检索能力并验证，不应更换 ASR 来解决知识问题。

## 4. 最终验收与未验证范围

2026-11-03 实际完成：

- 浏览器实时语音往返与合成语音两轮测试。
- SIM 回声测试，接听人确认听到提示音与回声。
- 服务器 SIP 夹具输入、ASR、LLM、返回音频。
- 授权 SIM AI 电话，连续两轮用户提问被识别并得到回答；观察窗口双方各约 4,500 音频帧，峰值分别约 28,123 和 26,956；RTP 采样统计丢包为 0。
- 用户随后确认当前体验良好；代码与 README 已提交，`v1.0.0` 源码基线的自动部署成功。

以上不等于完成并发、长时间运行、全部网络、手机重启恢复和所有安卓机型的可靠性验收。帧数、峰值和丢包统计也不代替延迟、音质与插话听感评估。
