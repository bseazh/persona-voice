# 采购供应商沟通工作台 v1

入口：https://phone.hehaizhao.site/consult （管理员登录）。新增采购供应商沟通模板，复用会话、历史、实时转录、报告与 Markdown 导出；旧睡眠/自由对话记录保持各自原模板，不迁移为采购记录。

## 使用

1. 在新建沟通任务选择“采购供应商沟通”，填写项目需求表：项目、供应商、场景、处理量及单位、期望产物、约束。本表仅填可对供应商披露的信息，不能放内部底价等机密。
2. 先选择文字咨询验证问法；网页语音选择原流水线或 Qwen 全双工。电话拨号页面也有独立项目表，仍须通过号码白名单、线路检查和人工拨号确认。
3. AI 顺着回答选择一个相关的重要缺口追问，不按题号念清单。对方只做单机就核实单机供货，已回答不重问，拒答不强追，不承诺付款或订单。
4. 结束后查看采购报告：供应商角色、场景与工况、配置、案例、商务、交付售后、行动项。报告与完整转录分开下载；需求表随会话保存，也写入导出。

文字模式每轮采集带用户消息引用的事实；语音模式保留实时对话，结构化事实在结束报告时统一抽取，不宣称已实现后台实时字段提取。所有供应商口头信息仍需核验；AI 报告不是正式报价或供应商准入结论。当前没有知识库。

## 问题如何生成

输入是固定版本采购模板、当前项目需求、双方历史对话。模板规定目标、问法、权限与结束要求；模型自由组织口语表达，按缺口追问，不是固定录音或题库顺序。当前缺口主要由模型根据上下文判断，并非严格强制状态机。

```text
项目需求表 + 采购规则 + 对话历史
                 ↓
文字：DeepSeek 生成回复与带出处的结构化字段
语音流水线：ASR → DeepSeek → TTS → LiveKit
原生实时：音频 → Qwen Realtime 内置理解/生成/发声 → LiveKit
                 ↓
最终文字持久化 → 结束 → DeepSeek 分析报告 → 报告/转录导出
```

Qwen 原生实时的模型本身决定每句回答，不能直接把它内部 LLM 换成 DeepSeek。外部可以提供任务指令，未来也可用检索/工具/业务控制补充资料，但需验证该接口和适配器的支持，不意味着模型内部被替换。若必须由外部指定 LLM 控制每一句，用 ASR + 外部 LLM + TTS 更明确，代价是串接和轮次协调等待。

本版原生实时通话仍是 Qwen 主导对话，DeepSeek 只在通话后整理报告；没有再并行加一个同步“主管模型”到每轮音频路径，不额外增加该项延迟。自然度、字段覆盖和供应商角色追问需真实样本验收，不能仅凭成功注入指令宣称全通过。

## 实现与验证

- web/lib/procurement.ts：模板、项目白名单与长度校验、自然问法、报告提示。
- web/lib/consultation.ts：按模板采集字段、证据 ID 校验、采购报告与导出。
- web/app/consult/project-form.tsx、workspace.tsx、phone-dial.tsx：项目表、需求快照、既有对话与报告入口。
- 两个 consult API：模板快照持久化、电话幂等校验、按会话下发业务指令；其他路线暂不接受采购语音模板。
- services/agent/agent.py、consultation_voice.py、realtime_voice.py：让语音助手使用该会话采购指令与开场。
- scripts/test-procurement.cjs：必填、字段类型、长度及模板隔离校验。
- scripts/validate-procurement.cjs：公开 HTTPS 上真实 DeepSeek 文字咨询验收，使用明确标注的虚构供应商回答，不拨号；保存结果供人工审查自然问法，不把接口成功冒充真人体验。

无数据库破坏性迁移。日志保留动作与证据，不保存模型内部思维链。结束语/手机释放仍应独立验收；本版不自动拨号测试。
