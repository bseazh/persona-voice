# 专用手机电话网关：日常启动、恢复与验收

## 目前已经具备什么

云端 AI Agent、LiveKit、SIP 桥、Asterisk 和私有电话控制台均作为常驻服务运行。日常拨号不需要人工重新启动 AI Agent。控制台监听服务器 `127.0.0.1:5055`，不配置 Caddy 路由、不对公网监听，通过 SSH 本地转发访问。

控制台支持：实时查询注册/线路状态、只从允许名单选择号码、单通电话互斥、重复提交保护、挂断本控制台发起的电话。不是全功能 PBX 管理界面；不会挂断其他来源的通话。

### 左右对话内容

控制台的“实时对话”区显示接听人（左）和 AI 小禾（右），每句话确认后更新，不是逐字流式字幕。由 Agent 会话事件提供内容，AI 被打断时标记“已打断”。文字出现不证明接听人实际听到了声音。

仅显示最近的 `sim-ai-` 电话房间，不显示普通浏览器会话。文字临时保存于服务器 `/run/persona-phone-transcripts`（ubuntu 写、asterisk 读），不写入应用日志或 Git，不保存音频。30 分钟无更新后接口不再展示；文件由 systemd-tmpfiles 定期清理或服务器重启清除，并非精确 30 分钟物理擦除。旧通话没有追溯补录。使用前应告知接听人存在实时文字转写。

## 日常使用（macOS）

1. 拨号手机保持联网、Voice SIP Agent 正常、Shizuku 已授权；不要把 USB 当作音频线。
2. 双击 `scripts/打开电话控制台.command`，按需输入 SSH 登录密码。使用密钥登录时无需输入密码。终端窗口保持打开。
3. 浏览器打开 `http://127.0.0.1:5055`，账号 `operator`，使用独立控制台密码。当前电脑已生成的凭据文件在忽略目录 `BigApple输出/android-gateway/phone-console-access.txt`；不要上传或分享该文件。
4. 看到网关在线、线路空闲后，选择号码，确认接听人已同意，勾选确认框再拨号。
5. 结束时点击挂断或由接听端挂断。关闭网页/SSH 隧道本身不会结束正在进行的通话。

Linux 或其他终端可运行 `bash scripts/open-phone-console.sh`，再手动打开网页。隧道绑定电脑 loopback，不允许局域网其他设备直接访问。不要把监听地址改成 `0.0.0.0`，也不要给公网域名增加控制台代理。

隧道提示端口占用时，先确认是否已经打开控制台窗口；不要杀掉不明进程。关闭自己之前的隧道窗口，再重试。

## 时长与号码保护

- 服务器 `/etc/persona-phone-console.env` 保存精确号码名单与随机密码，权限 0600。网页不能修改名单。
- `[console-outbound]` 仅匹配当前测试号码；网关白名单和 `X-VSA-Dial` 仍是独立保护。新号码要同步配置这三处，不能只改网页。
- 控制台保留 Local 通道（`/n`），便于精确挂断和保留生命周期限制。
- Asterisk `Dial` 在手机腿和 LiveKit 腿都设置 `L(180000)`，即接通后至多约 180 秒；控制台拨号腿另有 220 秒绝对限制兜底。
- 这是新加入的限制加固：原本仅依赖 Local 通道的绝对超时，可能受通道优化影响。真实 180 秒到时断开还需要专门验收，不应仅根据配置宣称实测通过。
- 拨号提交后保留约 40 秒防重复窗口，短通话结束后可能需要稍等才允许下一次拨打。

## 一键检查与恢复

电脑安装 ADB，USB 连接并解锁手机。双击 `scripts/检查恢复手机网关.command`。

该工具会检查：USB 是否唯一在线/已授权、网关状态、Shizuku、音频后端、SIM 状态和服务器 SIP 注册。在无法确认没有手机通话时拒绝恢复。恢复模式尝试根据安装位置启动 Shizuku，并在它连接后重启网关 SIP。

不会做的操作：拨号、修改测试号码、自动更换 SIM、重启手机、绕过 USB 授权或系统权限。USB 未授权需要在手机确认；Shizuku 未授权需要在手机应用确认。服务器检查需要 SSH 权限，桌面双击版可提示输入密码，不把密码写进脚本。

仅检查、不改变状态：

```bash
python3 scripts/gateway-check.py
```

明确恢复并允许 SSH 提示密码：

```bash
python3 scripts/gateway-check.py --recover --interactive-ssh
```

多个设备时加 `--serial <设备序列号>`。默认服务器可通过 `--server ubuntu@地址` 指定。恢复后 SIP 注册可能需要一点时间，应再检查，不以恢复命令返回成功代替注册成功。

## 脱离 USB 验收

1. USB 仍连接时确认网关和服务器注册正常，记录时间与网络。
2. 用户实际拔线，保持手机网络，电脑 `adb devices` 不应再列出该 USB 设备（另有无线 ADB 时需区分）。
3. 等待至少 60 秒后确认服务器仍 `Avail`，排除旧注册条目尚未过期的假象。
4. 接听人明确准备好后，通过控制台发起一次电话，测试 AI 问候和连续两轮问答。
5. 用控制台挂断，确认手机结束通话、控制台恢复空闲。
6. 另一次授权测试保持通话至时限，确认自动结束。不要把用户提前挂断误写成超时验证通过。

## 手机重启恢复验收

必须由用户确认当前无其他重要手机任务，再重启专用手机。不要在后台擅自重启。

记录重启后是否自动联网、网关是否启动、Shizuku 是否可用、SIP 是否重新注册。非 root 手机上的 Shizuku 常需要重新启动；系统后台限制也可能阻止网关恢复。若需要 USB 或无线调试人工操作，按事实记录，不能称为全自动恢复。

需要人工恢复时连接 USB，运行恢复工具并完成手机授权，再按脱线验收重测。不要为了免重启恢复而未经评估解锁 bootloader 或 root。

## 待机验收与记录

建议分为锁屏待机 30 分钟、2 小时、过夜三个阶段。每阶段记录：网络、是否充电、注册是否在线、系统是否杀后台、一次授权通话的听感、挂断后是否回到空闲。观察在线不等于已测试通话。

## 管理员部署与检查

初次安装或更新控制台是显式操作（须无活动电话）：

```bash
sudo python3 scripts/setup-phone-console.py
sudo systemctl status persona-phone-console --no-pager
sudo journalctl -u persona-phone-console -n 80 --no-pager
sudo ss -lntp | grep 5055
```

脚本将代码复制到 `/opt/persona-phone-console`，服务以 `asterisk` 用户运行，不授予 Web 进程 sudo。配置与部署目录分离。普通 main push 同步源码，但不会自动覆盖 `/opt` 中的控制台或轮换密码，更新该服务需要再次运行安装脚本。

控制台仅提供固定操作，不接受用户输入任意 Asterisk 命令。它依赖受信任的 SSH 接入、独立密码、Host/Origin 校验和 CSRF 请求头；不应作为公网多租户产品部署。

账号忘记或需轮换时由管理员读取/更换受保护的服务器配置，并重新安全分发，勿粘贴到聊天、工单或 Git。有关详细链路问题见 [故障排查手册](TROUBLESHOOTING.md)。
