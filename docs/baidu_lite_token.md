# 百度 Lite：两次两分钟电话的 Token、费用与逐响应时延

日期：2026-11-05。模型 `audio-mini-realtime-near`，音色 8003。

## 计费口径

官方价格：https://cloud.baidu.com/doc/SPEECH/s/Tmq8y6vdh （页面更新时间 2026-07-17，本次查阅 2026-11-05）。

|Lite 用量类型|后付费单价：元/千 token|
|---|---:|
|输入音频|0.016|
|输入文本|0.002|
|输出音频|0.060|
|输出文本|0.016|

每个 response.done 的 response.usage 是本次实测计数来源。按 response_id 去重，分别累加 input_token_details / output_token_details 中的 audio_tokens、text_tokens。输入文本可能包含供应商计入的上下文等内容，当前无法进一步拆分来源，不能按用户可见字数替代。取消的回复若返回 usage 也计入；没有 usage 的回复必须标记缺测，不能当零。

模型标价费用 = (输入音频 × 0.016 + 输入文本 × 0.002 + 输出音频 × 0.060 + 输出文本 × 0.016) / 1000。

每分钟模型费用 = 该通模型标价费用 × 60 / 实际接通时长秒数。用户最新要求为每轮约 120 秒触发挂断，共两轮；释放耗时可能让实际时长略超过两分钟。接通时长与模型连接时长并不严格相同，分开记录。

这不是账户实扣。免费额度、资源包、折扣和账单延迟需在百度控制台核对；用户说有免费额度，本测试不启用后付费、不购买资源包。官方另列搜索增强 0.036 元/次，并说明接口自动开启搜索增强；若响应没有搜索调用次数，额外搜索费用记“未知”，不得按零计算。SIM 资费、腾讯云、LiveKit，以及结束后 DeepSeek 报告生成也不包含在模型标价费用中。

## 接入与限制

网页可选 baidu-realtime 路线，普通问答由百度直接处理，其他路线保留。接听后先说话；Lite 不支持自定义系统指令，本路线不宣称执行咨询模板。没有假冒主动开场、没有额外调用其他 TTS。控制台按当前 call ID 结束电话；口头结束则等待当前原生回复播放或超时后释放，不声称可指定原生结束语。

真实供应商 + LiveKit AgentSession 探针通过：用户与助手转录、音频输出、usage 审计均有记录。曾发现 Base64 换行导致严格解码失败，已通过去除空白后严格校验解决；未用宽松解码掩盖非法字符。另一直接 API 探针曾将两天小时数答成 144，保留为内容质量风险，联通成功不等于回答正确。

### 时延口径

第一轮 11 个可配对响应，“服务器收到百度 speech_stopped → 首音频到达 Agent”均值 **0.194581s**，最大 **0.992013s**。配对按最近一次停说事件、期间无新开始说话事件；这是事件时间配对，不是音频样本端到端 trace。它包含被中断的回答，不能与只计完整回答的旧表直接比较。

第二轮 6 个可配对响应，同一口径均值 **0.444076s**，最大 **0.909934s**。两轮完整保留停说事件接收、response.created 接收、首音频接收和 SDK 输出开始/结束时间戳；缺测值为 null，不补零。

**不能把这个数字当用户说完到手机听见的等待。** 多个百度停说事件与首音频集中到达，前面端点检测/模型处理已经发生但不在这个计时区间内。当前 SDK 转录记录缺少 stopped_speaking_at，助手也没有 e2e_latency，真实用户停说到听筒播放时延为 N/A。此前独立合成输入探针从输入文件发送结束到首音频为约 1.3～3.1s，也不是这通手机测量。必须补共同音频时钟或端侧观测后才能公平比较 Qwen/百度，不能用约 10ms 的事件间隔宣称近乎零时延。

公网房间验收 `6b574e45-25f8-4c8c-8c61-1573c6e4487d` 已确认客户端收到 178 个有声音频帧、正确转录与回答、后台结束后房间释放；这是电话之前的独立验证，不计入两轮真实电话。关闭房间时出现 RTC data channel closed 原生日志，不扩大声称为全系统无错误。

第一轮结束后线路曾被另一通豆包测试占用，等待空闲后才完成第二轮，未抢占现有通话。测试结束检查 Asterisk 无活动通话。第二轮部分回复输出持续约 25.5 秒、20.0 秒；回答长度与打断体验仍需单独评估，本次不以联通成功宣称流畅度已达标。

## 首次电话尝试失败（保留，不计入两轮有效测试）
