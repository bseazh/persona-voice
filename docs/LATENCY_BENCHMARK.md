# 真实电话时延优化验收

## 执行顺序

基线 B0（2 通）→ ASR 收尾 B1（2 通）→ TTS 双向流 B2（2 通）→ 提前生成 B3（2 通）→ 简短发言 B4（2 通）。每阶段只改变一项，保存配置、代码版本、两通会话 ID 和逐轮计时。没有接通、无有效问答的拨号只记为失败尝试，不算有效测试。

每通使用相同接听号码、SIM、睡眠模板和尽可能相同的网络环境。接听方至少进行 5 轮：同意调研、描述作息、描述入睡、句中停顿后补充、插话纠正、主动结束。不要提供真实敏感健康资料；测试内容可以使用自己指定的固定例句，但模型回答必须是真实生成。

## 计时定义

- 总响应：LiveKit SDK 的 e2e_latency，即 VAD 标定用户停止说话至 Agent 开始输出音频，不包含手机实际听音确认。
- ASR 最终转录：transcription_delay。
- 轮次结束：end_of_turn_delay，包含与 ASR 收尾重叠的等待，不与转录延迟相加。
- 模型首字：llm_node_ttft。
- 首段送合成：llm_node_ttfs，从 LLM 开始计算，包含首字等待，不与首字直接相加。
- TTS 节点首音频：tts_node_ttfb。当前 SDK 优先使用音频帧携带的供应商合成开始时间；没有该时间才回退到首个文本片段时间，此时包含切句等待。存在 llm_node_ttfs 时可按首段送合成边界拆分；缺失时不强行拆分。
- 供应商首音频：TTSMetrics.ttfb，按 speech_id 匹配，保留每段记录。
- 手机听音：需要接听端独立计时；仅凭服务器时间不能给出精确数值。

只有互不重叠且对应同一轮的阶段才能计算占比。提前生成会产生重叠，此时使用时间轴和重叠说明，不强制凑成 100%。中断、开场、工具结束语分别列出，不混入正常问答均值。所有缺失值标记 N/A，不能当作 0。每通分别报告均值、中位数、最大值、有效轮数；两通小样本不宣称稳定 P95 或因果结论。

## 人工体验记录

每通记录：是否抢话、是否漏识别、打断后是否继续播放、是否有句间卡顿、结束语是否播放完整、手机听感等待。异常轮仍保留，不因耗时高而删掉。

## 运行

换卡后的新批次使用 `node scripts/benchmark-phone.cjs baseline-newline 1`，第二通使用 `baseline-newline 2`。脚本校验工作台的主被叫配置后拨号；不会更改物理 SIM 号码。历史 baseline 两次未接通记录不覆盖。请求 ID 先落盘，重复运行拒绝拨打，避免不确定结果下重复呼叫。输出在项目 BigApple输出/latency-benchmark，含私人转录，不提交 Git。

每次测试结束，必须将脱敏 Markdown 结果追加到对应 GitHub Issue，再将阶段报告和测量数据保存到 `docs/performance/` 并推送 GitHub。入口见 [时延优化跟踪](performance/README.md)。换手机或换 SIM 后重新建立基线，不把两种线路的差异算作软件优化收益。

完成两通基线并出报告前，不修改语音策略。先只增加 SDK 原始计时日志，各阶段保持同一套测量开销。
